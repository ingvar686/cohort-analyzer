# Altegio Cohort Analyzer

Локальный портал когортного анализа / LTV с обновлением данных из Altegio **без AI-токенов**.

Когортный отчёт поддерживает выбор филиала и маркетинговых категорий, тепловую карту выручки и числа клиентов, помесячные бюджеты, LTV, CAC, ROI и возвращаемость. В расчёт когорт входят состоявшиеся визиты с завершённой оплатой. Бюджеты сохраняются в браузере отдельно для каждого филиала.

Иконка заметки рядом с кампанией или её месяцем открывает небольшое окно для описания аудитории, предложения и креативов. Заполненная иконка выделяется; наведение показывает короткий текст. Заметки сохраняются в этом браузере отдельно для подключения, филиала, кампании и месяца. В Altegio и в передаваемый архив они не отправляются. Проверка хранения: `node scripts/check_campaign_notes.cjs`.

Отчёт возможностей допродаж находит клиентов с заданным числом посещений выбранных услуг и небольшим числом посещений других услуг или категорий. Полученную аудиторию можно выгрузить или добавить в категорию клиентов Altegio. Названия новых категорий и рассылок включают источник лояльности, точный порог визитов и направление допродажи. В каждой новой рассылке сохраняется снимок фильтров: исходная категория и услуги, пороги, целевая категория или услуга и дата истории. Этот снимок не меняется при смене фильтров отчёта. В старых рассылках отсутствие этих данных отмечается явно. Кнопка «Указать фильтры» позволяет один раз сохранить описание исходных условий вручную; аудитория, даты, расходы и результаты не меняются. В карточке такое описание помечается как добавленное вручную.

## Windows-приложение для клиентов

Готовый архив: `data/raw/AltegioAnalytics-Windows.zip`. Внутри — `AltegioAnalytics.exe` и короткая инструкция. Python, `.env`, API-ключи и чат не требуются.

1. Распакуйте архив и запустите `AltegioAnalytics.exe`.
2. Нажмите **Войти через Altegio**. Пароль вводится только на официальной странице Altegio в браузере.
3. Подтвердите доступ на чтение, выберите филиал и нажмите **Загрузить мой отчёт**. Телефоны для CSV можно подключить отдельной галочкой при входе.
4. Для последующих загрузок используйте **Обновить данные**. Окно приложения должно оставаться открытым; повторный запуск открывает уже работающий экземпляр.

Приложение напрямую обращается к read-only Altegio MCP, без ИИ-посредника. История клиентов и расчёты остаются на компьютере, в `%LOCALAPPDATA%/AltegioAnalytics`; токены зашифрованы Windows для текущего пользователя. Снимки разных подключений разделены. В архив не включены данные салонов или ключи разработчика.

В этой версии доступны когортный отчёт, бюджеты, подбор клиентов, CSV, создание рассылок и отслеживание их результатов. Получатели, услуги, сроки и расходы сохраняются локально отдельно для каждого подключения и филиала. Кнопка «Обновить результаты» читает свежие бронирования и полную карточку подходящих записей через MCP. Общая кнопка «Обновить данные» также обновляет результаты рассылок. Изменение категорий клиентов в CRM пока не поддерживается read-only MCP: соответствующая кнопка объясняет ограничение и предлагает CSV выбранной аудитории. Первый сбор полной истории может занять несколько минут. Это тестовая сборка без цифровой подписи; реальный вход и выдача прав требуют проверки пользователем в Altegio.

Для сборки из исходников на Windows:

```powershell
python -m pip install pyinstaller==6.22.3
python scripts/build_desktop.py
```

Сборщик включает только разрешённые файлы интерфейса и код локального приложения, проверяет готовый EXE и создаёт архив. Исходники запуска: `python scripts/desktop.py`. Проверки: `python -m unittest discover -s scripts -p 'test_*.py'`.

## Запуск серверной версии через API

1. Скопируйте `.env.example` → `.env` и заполните ключи.
2. Получите User Token (один раз):

```powershell
python scripts/auth_user_token.py
```

3. Для запуска сервера вручную:

```powershell
python scripts/server.py
```

4. Откройте http://127.0.0.1:8765/dashboards/index.html  
5. Выберите филиал в поле **Выбор филиала**. Категории, клиенты и данные когорт загружаются отдельно для каждого филиала.
6. Нажмите **Обновить данные**, чтобы получить свежие данные выбранного филиала из Altegio.

## Автоматическое назначение категорий

В основном отчёте откройте **Автоматизация**. Настройте пары «виджет бронирования → категория клиента», проверьте пробный прогон и только затем включайте автоматизацию. Она выключена по умолчанию. При включении сервер добавляет категорию в карточку подходящего клиента и сохраняет остальные категории. Требуются действующие Partner/User Token и права на редактирование карточек клиентов. Windows EXE с доступом только на чтение этот режим не поддерживает.

Рабочие правила хранятся отдельно для каждого филиала и подключения в `data/automation/`; там же остаётся журнал ID для восстановления после перезапуска. Имена, телефоны и токены туда не записываются. Когда компьютер выключен, обработчик ждёт. После следующего входа и запуска сервера он догоняет записи в окне расписания за предыдущий и следующий год. Altegio API фильтрует список по дате визита, поэтому записи за пределами этого окна не рассматриваются.

Чтобы сервер запускался после каждого входа в Windows, один раз выполните из PowerShell в корне проекта:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/install_automation_startup.ps1
```

Для запуска по требованию просто дважды щёлкните `Open Dashboard.bat` в корне проекта. Он проверит локальный сервер, запустит его скрыто, если он выключен, и откроет отчёт. Установщик выше нужен только если хотите автоматический запуск при входе в Windows без двойного щелчка. Статус сервера можно смотреть по адресу http://127.0.0.1:8765/api/health. Удаление автозапуска: `Unregister-ScheduledTask -TaskName 'Altegio Analytics local server' -Confirm:$false`.

Для текущего фонового режима условие нового клиента — отсутствие предыдущих состоявшихся визитов с полной оплатой. Отдельная пометка «Новый клиент» документированным API не гарантирована. Автоматизация начинает учитывать новые бронирования с момента её первого включения и не размечает задним числом весь клиентский список.

## Переменные `.env`

| Ключ | Описание |
|------|----------|
| `ALTEGIO_PARTNER_TOKEN` | Partner Token из Developer Account |
| `ALTEGIO_USER_TOKEN` | User Token (через `auth_user_token.py`) |
| `ALTEGIO_LOCATION_ID` | ID филиала (Casa House = `764940`) |
| `ALTEGIO_PARTNER_ID` | Partner ID (опционально) |

`.env` не коммитится в git.

## API сервера

- `GET /api/health` — статус и наличие токенов
- `GET /api/locations` — доступные филиалы текущего пользователя
- `GET /api/data?location_id=ID` — локальный snapshot выбранного филиала
- `POST /api/sync?location_id=ID` — синхронизация выбранного филиала с Altegio (0 AI-токенов)

Локальные файлы `data/portal_<location_id>.json` и история визитов/оплат не добавляются в Git. Снимок привязан к текущему подключению: при смене токенов он загружается заново. Доступ к филиалу проверяется через Altegio, а не по наличию файла на диске.

## Передача коллегам

```powershell
python scripts/package_project.py data/raw/altegio-analytics-share.zip
```

Архив содержит только приложение и инструкцию, включая настройки локальной автоматизации. В него не входят `.env`, данные салонов, демо-снимки, журналы или настройки IDE. Без собственных ключей отчёт показывает экран подключения. Вход в Altegio в соседней вкладке браузера не подключает локальный отчёт: получателю нужно настроить свой `.env` и запустить сервер по инструкции выше. `ALTEGIO_LOCATION_ID` можно оставить пустым — филиалы загрузятся из его аккаунта. Реальное назначение категорий выключено по умолчанию и требует отдельного включения самим пользователем.

Ручной sync из терминала:

```powershell
python scripts/sync_from_altegio.py
```

Проверка расчётов помесячных бюджетов и метрик (нужен Node.js):

```powershell
node scripts/check_monthly_budgets.cjs
```

## Важно

- Ключи API — секреты. Не публикуйте их в чат/репозиторий.
- Если токен уже светился в чате, лучше перевыпустить Partner Token в Developer Account.

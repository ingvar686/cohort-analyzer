# Автоматизация категорий

Локальная страница настройки правил «виджет бронирования → категория клиента». В основном дашборде открывается через пункт «Автоматизация».

Открыть при запущенном обычном сервере проекта:

http://127.0.0.1:8765/dashboards/automation-sandbox/index.html

Для хранения рабочих настроек и реального назначения категорий нужен сервер проекта, подключение Altegio через `.env` и разрешение редактировать карточки клиентов. На статическом хостинге и в read-only Windows EXE назначения категорий не работают.

## Что работает

- Выбор филиала Casa House или Massage salon Montmartre.
- Справочники реальных виджетов и категорий, прочитанные через Altegio MCP 18.11.2026. `catalog.js` содержит только ID и названия, без клиентов и токенов. Это снимок, а не фоновое обновление справочников.
- Создание, изменение, удаление и отключение правил. Один виджет — одно правило в рамках филиала.
- Условия «нет предыдущих состоявшихся визитов», «явная пометка нового клиента», «все клиенты».
- Назначение при бронировании, после состоявшегося визита или после визита с полной оплатой.
- Период кампании по дате создания бронирования.
- Защита уже известного первого источника привлечения, сохранение прочих категорий, пропуск повторных событий и отмен.
- Сохранение правил сервером в `data/automation/` отдельно для филиала и подключения. `localStorage` — только локальная копия интерфейса; экспорт JSON не содержит токены и данные клиентов.
- Фоновый опрос бронирований в режиме «При бронировании» с условием «Новых — нет предыдущих состоявшихся оплаченных визитов». Состояние последнего запуска, повторов и очереди ошибок сохраняется локально, повторно одна запись не обрабатывается.
- Настройки запуска хранятся в `data/automation/settings_<ID филиала>.json`, журнал служебных ID — в `state_<ID филиала>.json`. Файлы исключены из Git и архива для коллег.
- Пробный прогон по вымышленным событиям и ручной конструктор тестового сценария.

## Границы прототипа

Пробный прогон остаётся симуляцией. Реальный режим выключен по умолчанию и запускается только после включения переключателя и нажатия «Сохранить правила». После этого сервер напрямую читает Altegio API и добавляет назначенную категорию, сохраняя остальные категории клиента.

Документированный API не гарантирует отдельный флаг «Новый клиент», поэтому рабочая проверка использует отсутствие предыдущих состоявшихся визитов с полной оплатой. Если история клиента недоступна, правило не помечает его как нового. Опрос охватывает записи расписания за последний и следующий год; это окно связано с тем, что API фильтрует по дате визита, а не по времени создания бронирования.

Пока локальный сервер выключен, обработчик не работает. Чтобы он автоматически запускался после входа пользователя в Windows, один раз выполните `powershell -ExecutionPolicy Bypass -File scripts/install_automation_startup.ps1`. Настройка создаёт задачу Планировщика Windows; её можно удалить командой из вывода установщика. Автозапуск не означает круглосуточную доступность: компьютер должен быть включён, пользователь должен войти в Windows и иметь интернет.
